## What the project is

We distill a **parallel multi-agent orchestrator** (the idea of Kimi K2.5 Agent Swarm) from a big Qwen
teacher into a ~2B Qwen student, using **MedCalc-Bench Verified, rule-based calculators** (clinical scores).

```
note + question + calculator variable spec
  -> ORCHESTRATOR: spawn_subagent(variables=[...], instructions=...) x N in one turn (parallel)
       -> SUB-AGENT: reads the note, returns JSON {var: {value, evidence (verbatim quote)}}
          validator (types/units/options + evidence substring), 1 retry with the error list
  -> calculate()  (no args: merges validated values, runs the OFFICIAL MedCalc-Bench code) -> answer
```

Research question: does learned coordination beat **the same 2B model as a single agent**
(`--mode single` = one sub-agent that gets all variables, same prompt format), which is the key control?
Frame the result as a hypothesis test. A null result is fine and expected by the literature:
multi-agent gains saturate when the single agent is already above ~45% (Kim et al. 2025).

## Known risks and untested assumptions (verify, don't trust)

- **`train_sft.py`:**
  - It loads with `AutoModelForCausalLM`, but Qwen3.5 is multimodal. If loading fails, use `AutoModelForImageTextToText`,
    or switch the student to Qwen3-1.7B.
  - It passes `processing_class=tokenizer` to dodge TRL's "assistant-only loss not supported for VLMs" error (trl#5471).
  - The template `qwen3_5_nothink_training.jinja` is assumed to ship inside TRL ≥ 1.18; `--chat-template` resolves the file name there.
- **`serve.sh`:**
  - Flags come from the vLLM Qwen3.5 recipe and the AWQ model card; they have not been run.
  - `--language-model-only` may not apply to the merged student checkpoint. Drop it if vLLM complains.
  - The parser is chosen by path pattern (`*qwen35*` → qwen3_coder), so the merged output dir must be `runs/sft_qwen35`.
- **Thinking is off everywhere**, via `chat_template_kwargs.enable_thinking=false` in `harness.LLM`.
- `harness.MAX_ORCH_TURNS=4`, `MAX_SUB_ATTEMPTS=2`, `max_tokens=1024` per call. Raise `--max-tokens` if outputs get truncated.

## Design decisions already agreed (don't relitigate without a reason)

- **Dataset:** MedCalc-Bench Verified, despite label noise. The alternatives (TCGA TNM, n2c2, MIMIC) are worse or need
  credentialed access, and the noise is handled explicitly with the oracle and the exclusions.
- **Models:** Qwen family only. The teacher is Qwen3.6-35B-A3B AWQ (fallback Qwen3-30B-A3B AWQ); the student is
  Qwen3.5-2B (fallback Qwen3-1.7B).
- **Training:** SFT with LoRA in bf16 (not QLoRA), loss on assistant tokens only. RL (PARL/GRPO) is "next steps" in the slides.
- **Calculator:** `calculate()` uses the official code even with its known bugs, so the metric stays comparable to
  the labels; "not mentioned" defaults are applied in code (absent = 0 points).
- **SFT filter:** keep a trajectory only if it is correct, oracle-consistent, has no errors and every sub-agent
  output is valid; at most 1 per row and 200 per calculator.
- **Honest caveat for the talk:** given the spec, decomposition is nearly deterministic. What the 2B can learn is
  grouping, instructions and re-querying. Report per-variable accuracy and critical steps next to final accuracy.
- **Not for clinical use;** say so on a slide.
